## 2. Hard Rules of Remediation

1. **Fix the Generator, Not Just Generated Leaves**:
   - Everything under `specs/agents/`, `rigs/`, `rosters/`, and `registry/` is deterministically generated by `scripts/generate-rigs.py`.
   - If a finding identifies a defect in `rig.yaml`, `agent.yaml`, `configurations.yaml`, `behaviour.json`, `status.json`, `bundle.yaml`, `guidance/role.md`, `runtime/mcp.json`, or `runtime/policy-enforcement.json`, fix the root cause in `scripts/generate-rigs.py` AND re-run `python3 scripts/generate-rigs.py` so the fix persists across regenerations and all cryptographic digests (`configurationId`, `packageDigest`, `bodyDigest`) stay synchronized.
2. **Strengthen `scripts/verify-rigs.sh` on Any Survived Sabotage**:
   - If the audit's Sabotage Results table shows that any `[S]` invariant survived sabotage (`Caught? = No`), add an explicit, fail-closed check to `scripts/verify-rigs.sh` and verify that breaking the invariant in a scratch copy causes `./scripts/verify-rigs.sh` to exit 1.
3. **Never Weaken Security, Tests, or Schema Validation**:
   - Never delete or skip a check in `scripts/verify-rigs.sh` or `scripts/audit_loop.py`.
   - Never weaken `builtin:locked` on the 16 read-only-charter roles.
   - Never enable `POST`, `BUILD`, `EXEC`, `VOLUMES`, `NETWORKS`, or `AUTH` on `docker-socket-proxy`.
   - Never bind a sidecar host port to `0.0.0.0` or introduce a `:latest` tag.
   - Never add symlinks inside `specs/` or `rigs/`.
   - Never place secrets or `OPENRIG_*` variables into `rig.yaml` `env:`.
4. **Stop After 3 Failed Attempts on the Same Error**:
   - If the same fix fails verification 3 times, record the exact commands and outputs in `docs/NOTES.md` and `REMEDIATION_LOG.md` rather than guessing blindly.
